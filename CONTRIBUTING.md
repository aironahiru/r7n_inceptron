# Contributing to Inceptron

First of all, thank you for your interest in Inceptron! 🎉

Inceptron is a young project, and every idea, question, bug report and pull request helps shape it. This guide explains how to get involved.

## 💬 Ways to contribute

- **Share ideas.** Open an issue using the *Idea or feature request* template. Concrete examples help most, like a theorem you'd want to prove and how you'd want the proof to look.
- **Ask questions.** If something is unclear, others are probably wondering too. Use the *Question* template.
- **Point to prior art.** Papers, existing provers and decision procedures we should learn from are all welcome.
- **Report bugs.** Use the *Bug report* template. If a bug lets Inceptron accept a proof of a false statement, please say so: that kind of bug (a *soundness bug*) gets top priority.
- **Improve the docs.** Typos, unclear wording, missing explanations: small fixes are very welcome.
- **Write code.** Once the core lands, this guide will list good first issues and explain how the code is organized.

## 🧭 Before you start

- Please read and follow the [Code of Conduct](CODE_OF_CONDUCT.md).
- For anything bigger than a small fix, **open an issue first** so we can agree on the approach before you put in the work.
- Check the [existing issues](https://github.com/aironahiru/r7n_inceptron/issues) to see whether someone is already on it.

## 🔀 Making a pull request

1. **Fork** the repository and create a branch from `main` with a descriptive name, such as `docs/fix-typo` or `feature/linear-arith`.
2. **Make your change.** Keep each pull request focused on one thing; smaller PRs are reviewed faster.
3. **Write clear commit messages.** Use a short summary line in the imperative mood (for example, `Add parser for numerals`), followed by more detail if needed.
4. **Open the pull request** and fill in the template. Link the issue it addresses (for example, `Closes #12`).
5. **Respond to review.** Feedback is meant to improve the work, not to judge you. Ask if anything is unclear.
